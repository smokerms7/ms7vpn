# MS7VPN для Windows

## ms7.vs2.5: два ядра и TUN

В настройках можно выбрать **Xray** или **sing-box**, затем **TUN** либо
**Системный прокси**. Старые настройки сохраняются; ядро по умолчанию — Xray.

- Xray поддерживает прежние профили, включая XHTTP и mKCP. В TUN он остаётся
  ядром соединения с сервером, а sing-box направляет трафик адаптера в локальный
  SOCKS Xray. Сокеты Xray привязаны к физическому интерфейсу, адрес сервера
  разрешается до запуска TUN, поэтому трафик не зацикливается.
- При выборе sing-box соединение с сервером обслуживается самим sing-box.
  Поддерживаются VLESS, VMess, Trojan, Shadowsocks, SOCKS и Hysteria2;
  транспорты RAW/TCP, WebSocket, gRPC и HTTPUpgrade. XHTTP/mKCP требуют Xray.
- Официальный sing-box 1.14.4 может быть несовместим с новыми REALITY-серверами
  Xray (см. [upstream issue #4520](https://github.com/SagerNet/sing-box/issues/4520)).
  При ошибке проверки REALITY выбирайте Xray. Проверка сертификатов не отключается.
- TUN требует прав администратора и отключения других VPN. Он создаёт
  `MS7VPN-TUN`, управляет маршрутами IPv4/IPv6 и DNS через sing-box.
  Успех проверяется по маршрутам и запросу с IPv4-адреса адаптера MS7VPN;
  наличие обычного интернета больше не считается работающим TUN.
- Переход на системный прокси после сбоя TUN больше не происходит автоматически.
- Блокировка рекламы в sing-box использует встроенный базовый список; Xray
  продолжает использовать `geosite.dat`, если этот файл установлен.

Для сборки дополнительно нужен `bundle/sing-box.exe` из официального архива
[sing-box 1.14.4 Windows amd64](https://github.com/SagerNet/sing-box/releases/tag/v1.14.4).
SHA-256 архива: `99185d75d314a07dbba4a130c8ad986cbeb629a07927975636b341ca61f991df`.
Текст лицензии включён в `resources/sing-box/LICENSE`.

Локальная сборка: `BUILD_WINDOWS.bat`. Если старый тест winws завершается
ошибкой `cannot create ... autohostlist.txt`, можно явно исключить только
его: `BUILD_WINDOWS.bat --skip-zapret-dryrun`. Остальные тесты продолжают
выполняться. Готовый `dist/MS7VPN-Setup-Full.exe` содержит оба ядра;
онлайн-установщик до публикации нового релиза устанавливает опубликованную
версию GitHub, поэтому для локальной проверки используйте полный.

Проверка конфигураций и старта настоящего sing-box без изменения маршрутов:

```powershell
$env:MS7_SINGBOX = (Resolve-Path bundle/sing-box.exe).Path
go test ./...
```

`cmd/vpncheck` — ручная проверка действующей подписки для обоих ядер. Временный
профиль удаляется после остановки ядер, исходная подписка не изменяется.
Не запускайте её параллельно с обычным MS7VPN. Для TUN отключите другие VPN
и запустите терминал от администратора:

```powershell
go run ./cmd/vpncheck -mode tun -report tun-report.json
```

Отчёт может содержать диагностические сетевые адреса; не публикуйте его.

VPN-клиент на Go: ядро Xray, интерфейс на HTML в окне WebView2.

## Сборка

Нужен только Go 1.23 или новее. Зависимости лежат в `vendor/`, интернет для
сборки не требуется.

```
BUILD_WINDOWS.bat
```

Скрипт собирает приложение, деинсталлятор, упаковывает `payload.zip` и
установщик. Готовые файлы появятся в `dist\`.

Перед сборкой положите в папку `bundle\`:

| Файл | Откуда |
|---|---|
| `xray.exe` | [Xray-core v26.3.27](https://github.com/XTLS/Xray-core/releases/tag/v26.3.27), архив `Xray-windows-64.zip` |
| `wintun.dll` | [Wintun 0.14.1](https://www.wintun.net/), папка `bin/amd64` |
| `MicrosoftEdgeWebview2Setup.exe` | [Evergreen Bootstrapper](https://developer.microsoft.com/microsoft-edge/webview2/) — необязательно |

Эти файлы в репозиторий не кладутся: они большие и распространяются своими
проектами под своими лицензиями.

## Выпуск новой версии

Приложение проверяет обновления через GitHub: берёт последний выпуск этого
репозитория, номер версии — из метки выпуска, установщик — из вложений.

1. Поднять номер в `VERSION`, `internal/model/model.go` и
   `internal/setup/setup_windows.go`
2. Собрать: `BUILD_WINDOWS.bat`
3. Releases → Draft a new release
4. Tag: `ms7.vs1.3` (схема номеров — `ms7.vsМАЖОРНАЯ.МИНОРНАЯ`)
5. Приложить `dist\MS7VPN-Setup.exe`
6. Publish

Адрес проверки меняется в самой программе: Настройки → Проверка обновлений.
Кроме ссылки на репозиторий там принимается адрес своего файла `latest.json`
вида `{"version": "...", "url": "...", "sha256": "...", "notes": "..."}`.

## Устройство

| Папка | Что внутри |
|---|---|
| `cmd/ms7vpn` | точка входа приложения |
| `cmd/installer`, `cmd/uninstaller` | установщик и деинсталлятор |
| `internal/app` | подключение, состояние, локальный HTTP API |
| `internal/xray` | сборка конфигурации Xray, запуск ядра, счётчики трафика |
| `internal/subscription` | разбор подписок и запрос сведений у панели |
| `internal/webui` | окно WebView2, в `assets/` весь интерфейс |
| `internal/tray` | значок в области уведомлений |
| `internal/update` | проверка обновлений |
| `internal/singleton` | запрет второй копии |

Данные пользователя лежат в `%APPDATA%\MS7VPN`, программа — в
`%LOCALAPPDATA%\Programs\MS7VPN`.

## Проверки

```
go test ./...
```

Тесты не требуют сети. Отдельно можно прогнать разбор счётчиков трафика на
настоящем ядре:

```
set MS7_XRAY=C:\путь\к\xray.exe
go test ./internal/xray -run TestStatsAgainstRealCore -v
```
